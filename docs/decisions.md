# Decisions

Append new entries; never silently change old ones. Format: `D<n> (date): decision. Why.`

**D1 (2026-10-18): Rust only, native egui/eframe on wgpu.** No Tauri, Electron, webview or JavaScript UI. One language, one binary, and the engine stays shared with the CLI and MCP.

**D2 (2026-10-18): Product is "Inbetween"; the CLI binary is `ib`.** Crates are `inbetween-*`, the desktop binary is `inbetween`, project files are `.inbetween` and dot sets `.inbetweendots`. `ib` is short to type for a tool used constantly from a shell.

**D3 (2026-10-18): Layering enforced by `cargo xtask layers`.** A crate may depend only on strictly lower layers, and UI crates are banned below L6. Registry lives in `xtask/src/layers.rs`. It keeps the engine reusable headless and wasm-clean.

**D4 (2026-10-18): Panicking forms banned in non-test code.** Crate-level `deny` attributes plus `clippy.toml` test exceptions, and `unsafe_code = "forbid"` workspace-wide. Hostile input must produce errors, not crashes.

**D5 (2026-10-18): Licences restricted to permissive ones.** `deny.toml` allows MIT, Apache-2.0, BSD, Zlib, ISC (plus Unicode and CC0 for data crates).

**D6 (2026-10-18): `xtask` uses `serde` and `serde_json` to read `cargo metadata`.** Both are MIT/Apache-2.0 and avoid hand-parsing manifests.

**D7 (2026-10-18): Delaunay via `spade` (MIT/Apache-2.0), geometry in `f64`.** Exact predicates make the triangulation robust to collinear and near-degenerate dots, so we do not write our own. Duplicate dots are rejected with `DuplicateDot { first, second }` rather than silently merged, so paired dot sets keep their indices. Collinear dots and fewer than three dots are accepted because the four frame corners always give the mesh area. A dot on a frame corner replaces that corner. Dots outside the frame are allowed; the mesh then covers their convex hull, which contains the frame. `MAX_DOTS` is 100,000.

**D8 (2026-10-18): Working pixels are premultiplied f32 holding sRGB-encoded values (no linearisation).** The 8-bit sRGB boundary then only divides or multiplies by 255 and premultiplies, so every non-transparent 8-bit pixel round-trips exactly (tested for all 255 alpha x 256 colour values), and t=0 / t=1 frames match the sources. Dissolves therefore blend in display space, as users of image tools expect; a linear-light option can be added later by converting at the same boundary. Fully transparent pixels normalise to `[0,0,0,0]` on output.

**D9 (2026-10-18): Image coordinates put pixel centres at +0.5; sampling is bilinear with edge clamp on premultiplied values.** Premultiplied interpolation is alpha-correct (no dark fringes next to transparency). NaN and infinite positions are clamped, never propagated.

**D10 (2026-10-18): PNG and JPEG via the `image` crate with only the `png` and `jpeg` features** (MIT/Apache-2.0). Decode checks the header against limits first (side at most 32,768, at most 100,000,000 pixels). 16-bit PNGs reduce to 8-bit. JPEG output has no alpha, so it composites over white. The `codecs` crate has no workspace dependencies; file helpers are `cfg(not(wasm32))`.

**D11 (2026-10-18): `cargo xtask wasm` checks every registered L0 to L5 crate for `wasm32-unknown-unknown`,** and runs in `xtask ci` and GitHub Actions.

**D12 (2026-10-18): Dot coordinates live in output-frame pixels** (y down, origin top-left). Sources of other sizes are fitted to the output first, so dots are placed on the fitted images. Fit modes: `stretch` (default; each axis scaled independently), `contain` (uniform, transparent bars) and `cover` (uniform, cropped). Only `contain` reads transparent outside the source; the others repeat edge pixels. Same-size sources fit as an exact identity.

**D13 (2026-10-18): One shared mesh, built from Image 1's dots; the last frame uses a mesh from Image 2's dots.** The default policy (`frame0`) triangulates once and reuses the connectivity, interpolating vertex positions. When dots move far the shared mesh can fold in the middle of the sequence, but frame 0 is Image 1 and the last frame is Image 2 exactly because the end frames use their own meshes. `per_frame` re-triangulates each interpolated frame, falling back to the shared mesh on frames where two dots coincide. Duplicate dots on either image are an error that names the image.

**D14 (2026-10-18): Frame time is `i / (n - 1)`; a one-frame sequence is Image 1.** `Point::lerp` is now written `a*(1-t) + b*t` so it returns `a` at t=0 and `b` at t=1 bit-exactly.

**D15 (2026-10-18): Deterministic parallel rendering.** Each mesh triangle renders into its own buffer (rayon `par_iter().collect()` keeps order); buffers merge sequentially in triangle order, so overlapping or shared-edge pixels resolve the same way on any thread count. Pixel centres count as inside a triangle with `1e-9` slack so shared edges leave no gaps; any pixel still unclaimed (folded meshes) is sampled unwarped. If the inverse map for a layer is singular, that layer is sampled unwarped in that triangle.

**D16 (2026-10-18): File formats are JSON in a named, versioned envelope.** `.inbetween` is `{"format":"inbetween-project","version":1,"project":{...}}` and `.inbetweendots` is `{"format":"inbetween-dots","version":1,"pairs":[...]}`. JSON (via `serde_json`, MIT/Apache-2.0) keeps files diffable and writable by agents. The marker is checked before the body so a wrong or newer file gets a clear message. Reading ignores unknown fields and defaults missing ones, so adding an optional field never needs a version bump; a higher version than the build knows is refused (`NewerVersion`), never half-read. A UTF-8 BOM is tolerated.

**D17 (2026-10-18): Reading is bounded and writing is safe.** Files over 64 MiB, projects over 10,000 sequences, and any model-limit breach (frames, dots, output size, non-finite numbers) are errors. Image paths must be relative: absolute paths, drive letters and UNC paths are rejected on read and write; `..` is allowed so a project can sit beside an `images` folder. `make_relative` builds such paths lexically. Writes go to a temporary file in the same directory and are renamed over the target, so a full disk or crash leaves the old file intact; an invalid project is never written.

**D18 (2026-10-18): Parser robustness is tested twice.** `crates/format/tests/robustness.rs` runs deterministic mutation fuzzing on stable Rust in every `cargo test` (all truncations, all single-byte changes, 60,000 mutated seeds, random bytes, depth bombs), asserting no panic and write/read stability. `fuzz/` holds libFuzzer targets (`project`, `dots`) run by `.github/workflows/fuzz.yml`: 3 minutes per target on pull requests touching `format`, `doc`, `geom` or `fuzz`, 15 minutes weekly. The fuzz crate sits outside the workspace because `libfuzzer-sys` carries the (permissive) NCSA licence, which `deny.toml` does not allow.

**D19 (2026-10-18): Commands are data plus two function pointers.** A `CommandSpec` has an id, label, menu path, shortcut, description, a static parameter schema (`ParamSpec`: name, kind, required, range, default), an `enabled(&Session)` check with a reason, and `run(&mut Session, &Params)`. `Registry::run` validates parameters against the schema before `run` is reached: the value must be an object, unknown keys are rejected (the error lists the valid ones), types and ranges are checked, strings are capped at 4,096 bytes and may not contain NUL. Commands therefore never see raw JSON. `Registry::run_caught` additionally turns a panic into `CommandError::Internal` for shells that must keep going; tests use `run` so a panic stays visible. Commands live in `<area>_cmds.rs` modules with a `specs()` function. File-touching commands are compiled out on wasm32 (a platform service will replace them).

**D20 (2026-10-18): Image paths resolve against the project file's folder,** are re-checked as relative on every load, and loaded images are cached per `Session` keyed by full path with a (modified time, length) stamp, so a rendered sequence reads each source once and an edited file reloads. `export.sequence` numbers frames from 1 (`frame_0001.png`) and its `prefix` may not contain path separators. `sequence.length` accepts 2 to 999, matching the spec (hold frames arrive in M9); the model itself still allows 1 to 100,000.

**D21 (2026-10-18): Two bugs the M5 tests found, fixed at the source.** (1) serde_json parses floats one bit off unless its `float_roundtrip` feature is on, so dot positions drifted across save and load; the feature is now enabled and a 20,000-pair bit-exact test guards it. (2) Opening a Windows device name such as `CON` blocked forever; `read_file`, `read_project` and `read_dots` now refuse anything that is not a regular file.

**D22 (2026-10-18): The demo pair is generated, not photographic.** `testkit::demo` draws a sun face and a boxy moon face from formulas and returns matching dot pairs; `demo/` holds the rendered PNGs and project, and a test fails if they drift from the generator. No third-party assets, so no `ATTRIBUTION.md` row is needed.

**D23 (2026-10-18): Performance baseline and renderer structure.** `cargo xtask perf` runs `crates/render-cpu/examples/perf.rs` in release mode on a fixed 1080p, 1,000-dot scene at 4 threads, with a 100 ms budget (see `docs/perf.md`). The renderer shades 16-row bands in parallel: each band first records which triangle owns each pixel centre (later triangles win, as before), then colours its pixels. This removed the serial merge, halved the 4-thread time (52 to 28 ms) and made scaling near-linear, with a bit-identical checksum to the previous renderer. Per-triangle setup (bounds and inverse affine maps) still runs in parallel per triangle.

**D24 (2026-10-18): The GPU renderer draws the CPU's plan; tolerance versus the oracle is stated and tested.** `render-gpu` reuses `morph::Planner`, so the mesh and dissolve weight are the oracle's. Per triangle it builds three vertices carrying the output position and the matching position on each source (the oracle's inverse affine map, then the fit, evaluated on the CPU in f64). The GPU interpolates those linearly, which is exact for an affine map, and the fragment shader does the oracle's bilinear, edge-clamped, premultiplied sampling on `Rgba32Float` textures with `textureLoad` (no hardware filtering, so the maths matches). A full-frame unwarped quad is drawn first (the oracle's fallback for unclaimed pixels) and triangles then draw in plan order with no depth test, so later triangles overwrite earlier ones as in the oracle. Tolerances, in premultiplied channels (0.01 is about 2.5 of 255 levels), checked on 14 scenes in `crates/render-gpu/tests/matches_cpu.rs`: ordinary meshes must stay within max 0.01 and mean 5e-4 (observed: max 0.004, mean 7e-5, from GPU vertex snapping to a sub-pixel grid); folded meshes, slivers and the 1080p perf scene may have isolated pixels whose centre sits almost on a shared edge and is claimed by a different triangle, so they get max 0.5, at most 0.3% of pixels over 0.01, and mean 1e-3 (observed on the 1080p scene: 1 pixel in 2 million, mean 2.6e-5). Results are not bit-identical across GPUs or drivers; the CPU renderer stays the deterministic reference and is never adjusted to match the GPU.

**D25 (2026-10-18): Layer checks and licence checks for the GPU stack.** `xtask layers` skips the layer-order rule for dev-dependencies (they never ship, and GPU-versus-CPU tests need both renderers) but still bans UI crates below L6 for every dependency kind. `cargo deny check` now passes on the full tree (wgpu 24, naga, ash, windows crates, rayon, clap, image): licences, sources and bans are clean (`allow-wildcard-paths` for our own unpublished path dependencies). One advisory is ignored with a recorded reason: RUSTSEC-2024-0436 (`paste` is unmaintained), a build-time macro pulled in by wgpu's Metal backend. `cargo deny` had never run before this milestone.

**D26 (2026-10-18): CI runs the GPU tests on Linux against lavapipe (software Vulkan);** `INBETWEEN_REQUIRE_GPU=1` turns "no adapter" into a failure there. On Windows and macOS runners, and on any machine without a GPU, the tests print SKIP and pass. Source and output images are limited to the device's maximum texture size (`GpuError::TooLarge`); tiling larger outputs is still open (spec row "Output size not capped by the GPU").

**D27 (2026-10-18): The desktop shell is egui/eframe 0.31 on the same wgpu 24 as the renderer, and the licence policy was applied to it.** `ui-egui` (L6) holds all drawing; `apps/inbetween` is a thin `eframe::run_native` wrapper. Because eframe's wgpu device is shared (`GpuContext::from_parts`), the GPU renderer draws a frame straight into a texture egui paints; with no GPU the CPU renderer feeds an ordinary egui texture. Consequences for `cargo deny`: (1) egui's bundled fonts are under OFL and the Ubuntu Font Licence, outside our list, so `default_fonts` is off and the app bundles Roboto (Apache-2.0, `ATTRIBUTION.md`). (2) `BSL-1.0` (Boost, permissive like MIT) was added to the allow-list; it comes from the clipboard crates. (3) AccessKit is enabled for test builds only: the headless test harness needs it, but on Linux it pulls an AT-SPI stack with a known `quick-xml` vulnerability, so the shipped app leaves accessibility out for now (revisit when that dependency is fixed). (4) `exclude-dev = true`, and transitive "unmaintained" notices no longer fail the check (`unmaintained = "workspace"`); known vulnerabilities in anything that ships still do. The workspace Rust version moved to 1.85.

**D28 (2026-10-18): The shell only draws and reads input; the project changes through commands.** Canvases return `Action`s (add, select, drag, delete) and the app turns each into an engine command: `dots.add`, `dots.move`, `dots.delete`. Menus are generated from the registry (`menu` paths, shortcuts, `enabled` and its reason as a tooltip), so a new command appears with no UI change. A command needing input opens a form generated from its parameter schema, with a native file dialog for `Path` parameters (`PathUse` and extensions in `ParamSpec`). Keys the shell owns itself: Delete (needs the selected index), Escape, Space, F, arrows. All view state (zoom, pan, link, mesh and number toggles, selection, frame, fps, playback) lives in one serde struct, `ViewState`, persisted by eframe.

**D29 (2026-10-18): Editing semantics.** `dots.add` puts the partner at the same spot on both images (the person then drags it on one). Two dots may never share a spot on one image (`dots.add` and `dots.move` refuse, naming the image), so an edit can never make a project the renderer rejects. Edit commands are flagged `edits: true`: the registry snapshots the project first, records an undo step on success and restores the snapshot on failure. History keeps 200 steps. `edit.beginGroup` / `edit.endGroup` merge everything between them into one step; the shell wraps each drag in a group, so one drag is one undo step. `Session::revision()` changes on every edit, undo, redo and open, and drives cache invalidation (preview, mesh, source textures); `is_dirty()` drives the title asterisk. `project.new` takes two image paths (absolute is fine in memory); `project.save` rewrites absolute image paths relative to the file being written.

**D30 (2026-10-18): Preview colour.** The GPU preview target is `Rgba8Unorm` holding the sRGB-encoded premultiplied values the working space already uses, exposed to egui through an `Rgba8UnormSrgb` view (egui decodes sRGB textures to linear when sampling and re-encodes on output). Using the plain view double-encoded the colours and looked washed out; the real-window screenshot showed it. The M8 UI works on sequence 0; the sequence list is M10.

**D31 (2026-10-18): Morph types are a per-frame "mix" recipe; hold frames are timing.** `Mix::for_type(type, t)` in `inbetween-morph` gives each frame two weights, a brightness for each image and a mode: `Add` (`w1*s1 + w2*s2`, premultiplied) or `Over` (Image 2 scaled by `w2`, laid over Image 1). Morph is `(1-t, t)`; Morph Hold is `Over` with `(1, t)` so Image 1 never fades and shows through where Image 2 is transparent; Warp 1 and Warp 2 use one image at weight 1; Fade Out 1 and Fade In 2 dim an image's colour by `1-t` and `t` (alpha kept), skip the warp, and ignore the dots; Direct is Image 1 until `t = 1`, then Image 2. A weight of zero means that image is never sampled, so a type that does not use Image 2 renders without one (Warp 1, Fade Out 1). CPU and GPU share the recipe; the GPU gets it as five uniforms and a mode. Hold frames live on the sequence (`hold_start`, `hold_end`, 0 to 999 each, total capped by `MAX_FRAMES`): `Sequence::frame_time(index)` is 0 through the start hold, rises evenly across the morph frames, then 1 through the end hold. The morph frame count keeps meaning "including t = 0 and t = 1", so holds only repeat those two frames. Everything that counts frames (renderers, `export.sequence`, the preview, playback) uses `total_frames()`. Old files without the hold fields load with 0. New commands: `sequence.morphType`, `sequence.fit`, `sequence.mesh`, and `sequence.length` gained `hold_start` and `hold_end`. `ParamSpec::one_of` restricts a string parameter to a fixed set. "Enter as seconds" and apply-to-all for `sequence.length` are not done.

**D32 (2026-10-19): Curves are time remappings with pinned ends.** A `Curve` (doc) is 2 to 64 points with strictly rising x, all inside 0..1, running through the points left to right. The first point is (0, 0) and the last (1, 1) and neither may move, so the morph invariants hold with any curve: frame 0 is Image 1 and the last frame is Image 2. The spec's "caricature" overshoot is for the track curve (P2), not these. Between points the curve is a cubic Hermite spline with harmonic-mean tangents (zero at turning points), so it never overshoots a segment; `linear` switches to straight segments. `eval` clamps its input and output and falls back to the identity on a malformed curve, so a hostile file cannot panic or produce NaN, and `Sequence::validate` rejects malformed curves anyway (a project file with one fails to open). A sequence has two: the **feature curve** remaps the colour dissolve (`Mix::for_type(type, feature(t))`) and the **shape curve** remaps how far the dots have moved (`lerp(first, second, shape(t))`). The planner applies them, so CPU and GPU and every export agree with no renderer change. The mesh policy still switches to Image 2's mesh only at t = 1. Commands: `curve.feature` and `curve.shape` take an `op` (add, move, remove, linear, reset, apply_all); with no `op` they report the curve. The spec's `curve.edit` gestures are those ops. Master and track curves and the curve library are still open.

**D33 (2026-10-19): Multi-sequence projects.** A project's visible sequences play one after another in list order (`Project::total_frames`, `Project::locate`); hidden ones are skipped. `Sequence::visible` is saved (old files default to visible). List commands live in `list_cmds.rs`: `sequence.addBlank`, `sequence.add` (continues the previous sequence: Image 1 is its Image 2, frames, type, fit and mesh are inherited), `.delete`, `.duplicate`, `.rename`, `.visibility` (with `solo`, a toggle), `.reorder` (`move` or `to`), `.link` (a one-time copy of the previous Image 2 reference), `.copyFrame` (image plus its dots from one sequence into an image slot of another; the other side starts unmoved). `export.movie` writes every visible sequence as one continuously numbered series and `ib render` uses it unless `--sequence` is given (one sequence then renders as before). The shell keeps `ViewState::sequence`, the sequence the panels edit and the preview plays; `run_command` adds that as the `sequence` parameter to any command that takes one and was not given one, and the menu runs commands that need only `sequence` without a form. Changing the selected sequence clears the preview; list edits move the selection with them. Layer projects (`project.type.layer`) are P2 and not started.

**D34 (2026-10-19): Effects are a CPU post-pass on each sequence; the preview uses the CPU when any is on.** A `Sequence` carries `Effects`: a back colour, a background image with opacity, a mask (grayscale image, intensity -100 to 100, invert) and a foreground image with opacity. Layer order, bottom to top: back colour, background, the masked morph, foreground. Effect images are stretched to the output size and sampled bilinearly at pixel centres. The mask uses the luminance of the premultiplied pixel (a transparent mask pixel counts as black): positive intensity `i` scales the morph by `1 - i*(1 - light)` (dark areas hide it), negative scales it by `1 - |i|*light` (light areas hide it), and invert swaps light and dark first. The pass lives in `render-cpu` (`effects.rs`), runs after the morph and is skipped entirely when nothing is on, so the morph invariants hold with effects off and the oracle stays the only definition of the maths. `render-gpu` does not draw effects yet: the shell previews a sequence with any effect on through the CPU renderer (slower on large frames, correct everywhere), and `Prepared::renderer()` is the one place that builds a CPU renderer with its effect images. An enabled effect without a loadable image is an error, never a silent skip. Effect image paths follow the source-image rules (absolute in memory, relative when saved, checked on load). Commands: `effect.backColor`, `effect.background`, `effect.mask`, `effect.foreground`; each reports its state with no parameters, setting an `image` or `color` switches it on, `clear` resets it. Movie-level effects are not done, and `sequence.add` does not copy effects.

**D35 (2026-10-19): Animated export is pure Rust; video uses the user's ffmpeg.** `inbetween-export` (L4) encodes GIF (`gif` crate: per-frame NeuQuant palette, 1-bit transparency with alpha 128 as the cut, delays in whole hundredths so 60 fps plays as 50), APNG (`png` crate, full alpha, lossless) and animated WebP (each frame is a lossless still from `image-webp`; its VP8L chunk is re-wrapped in the VP8X/ANIM/ANMF container by hand, because no permissively licensed pure-Rust animated WebP encoder exists). All three buffer their frames (at most 1 GiB, checked before rendering starts) because APNG needs the frame count up front and duplicate dropping changes it. Video is not encoded in-process: H.264 and VP9 encoders are C libraries with patent and licence baggage the project avoids, so `export.video` pipes raw RGBA to an `ffmpeg` found on `PATH` (or given in `ffmpeg`), draining its stderr on a thread and turning a missing program or a failed encode into an actionable error. MP4 flattens alpha over the `matte` colour and rounds odd sizes down to even; WebM (VP9) and ProRes 4444 keep alpha. ffmpeg is an optional external program, not a dependency or a bundled asset. Shared options on every export: `fps` 1 to 60, `first`/`last`, `reverse`, and `drop_duplicates` (skip a sequence's first or last frame when it repeats the one before it, which is the join of continued sequences). `export.movie` takes `reverse` and `drop_duplicates` too; all of them go through `movie::render_movie`. Not done: cancel and progress, JPEG quality and DPI, a bundled encoder.

**D36 (2026-10-19): The P2 block is commands plus the CPU oracle; the GPU draws only what it always did.** (1) **Layer projects**: `Project::kind` (`sequence` default, or `layer`) is saved and switchable at any time with `project.type`, which changes no sequence. In a layer project every visible sequence plays at once, the first in the list on top; the movie is as long as the longest visible sequence and a shorter one holds its last frame (`Project::layers_at`). `export.movie` composites the layers with `over`; `locate` returns the top layer. The shell still previews the selected sequence only. (2) **Track curve** (`Sequence::track`): a bend shared by every dot, drawn in *chord space* (`u` along the dot's own start-to-end line, `v` sideways, in chord lengths), so each dot follows the same curve scaled and turned onto its own chord. A Catmull-Rom spline through 2 to 64 points; the drawn path minus the straight line is the bend, `tension` (0 to 20) scales it and the flips negate its two parts. The ends are pinned at (0, 0) and (1, 0) and the planner returns exactly the start and end dot at progress 0 and 1, so first and last frames still match the images; inner points outside the chord overshoot (caricature). It lives in `morph::Planner`, so the GPU renderer and every export get it with no change. Movable endpoints are not offered (they would break the first/last frame invariant). (3) **Master curve** (`Sequence::master_curve`): a `Curve` whose end points may sit at any height (`validate_free`, `set_end_y`), default flat at 1; it scales the whole finished frame, premultiplied. (4) **Camera** (`Sequence::camera`): keyframes of offset (in frame widths and heights), scale x/y (negative flips) and rotation about the frame centre, at morph times 0 to 1, up to 64, eased with a smoothstep between neighbours and held outside, with an optional easing `Curve` on the camera's clock. It resamples the rendered morph bilinearly before the effects (so effects stay fixed to the frame) and leaves uncovered areas transparent; with no moving keyframe it returns the frame untouched. (5) **Transition**: a grayscale image gives each pixel its own dissolve time, `start = light * (1 - soft)`, amount `= clamp((t - start) / soft)` with `soft >= 0.001` so 0 and 1 stay exact; the amount feeds `Mix::for_type` per pixel, so every morph type works and the feature curve still drives `t`. (6) **Light** pushes premultiplied colour towards white above mid gray and black below (alpha unchanged). (7) **Radial** draws 24 rays that fade towards the corners and turn half a turn over the morph, over the morph or under it (between the background and the morph). (8) **Trail** needs earlier frames, so only `render_frame(index)` draws it (`render_t` has no index): up to 8 earlier frames, skipping any that repeat the current time. Blur averages them with the current frame; a trail lays tinted, fading copies under it. Frame 0 never has a past, so it stays Image 1. (9) Like the D34 effects, all of these are exempt from the first/last-frame invariants while switched on (a trail or a camera move changes the last frame on purpose) and are checked only for validity, determinism and exact ends where the maths promises them (transition, master default, camera at an identity pose). `Sequence::needs_post_pass` (any effect, a moving camera or a master fade) sends the shell's preview to the CPU renderer. `Effects::all_images` / `all_images_mut` are the one list of effect image references for saving and path checks. Open: GPU versions, the sound effect, movie-level adjustments and filters, camera handles on the canvas, effect-level cameras, the curve library, a track editor window.

**D37 (2026-10-19): Face tools take a box or landmarks; no detector is bundled.** Auto-detection needs an ML model and an inference runtime (a large dependency and a model licence to vet), and a detector's output would still have to be mapped onto Inbetween's own landmark set. So `face.locate` places the model on a face box (default: a centred starting box to adjust with smart drag) or at landmark positions read from a `.inbetweenlandmarks` file, which any open landmark model can write in the order of the enabled model landmarks. Everything downstream (smart drag, extract, mix, library) works on the model's dots and does not care where they came from. A bundled detector can be added later behind the same file format without changing a command. Other choices: the model lives in the project (so it is saved, undone and scripted like everything else); a face is a run of dots in the model's order, addressed by `first`; smart drag is a Gaussian pull in model space with important landmarks following at 60%; mixing warps each face to the weighted mean shape with Warp 1 and blends colours by the feature weights; library dots are stored in the picture's own pixels so they fit any frame; random weights come from a splitmix64 stream, so a seed reproduces a mix exactly.

**D38 (2026-10-19): Dropping corner triangles leaves the uncovered frame transparent, and the exact-ends invariant applies only where something is drawn.** `Sequence::drop_corner_tris` (default off) makes the planner discard every mesh triangle that uses one of the four corner vertices; `FramePlan::backdrop` tells both renderers there is no fallback, so pixels no triangle covers are clear (the CPU skips its unwarped sampling, the GPU skips its full-frame quad) and the back colour or background effect shows through. At t = 0 and t = 1 every drawn pixel still equals the source; the area outside the dots' outline is transparent by design. With fewer than 3 dots (or dots whose outline is empty) the frame is fully clear. Pixels whose centre lies exactly on the outline edge may be claimed by only one renderer, so the GPU parity test uses its own tolerance (`OUTLINE`: a few edge pixels may flip between clear and drawn). The commands are `morph.option.dropCornerTris` and `morph.option.retriangulate`, both taking `on` (omit to report); `retriangulate` replaces the earlier `sequence.mesh` so the command id matches the spec. In the shell both are checkable menu items. Dots outside the image come from files, the CLI and MCP (or a drag past the edge); a click only adds a dot inside the frame.

**D39 (2026-10-19): Image import covers BMP, TIFF, TGA, GIF and PSD; export stays PNG and JPEG.** `codecs` adds the `image` crate's BMP, TIFF, TGA and GIF decoders (GIF reads the first frame). TGA has no magic bytes, so it is recognised only by the `.tga` extension (`decode_with_ext`, which `read_file` uses); every other format is sniffed from its bytes. PSD is read by an in-house reader (`codecs/src/psd.rs`) of the flattened composite at the end of the file: RGB or greyscale, 8 or 16 bits per channel, raw or PackBits, with the first extra channel as alpha; layers are ignored. CMYK, Lab, indexed, bitmap, 32-bit, PSB and ZIP-compressed data are "unsupported" errors, and every length is bounds-checked and the pixel count capped before anything is allocated. One list, `codecs::IMAGE_EXTENSIONS`, drives every command that offers an image path and the drop handler. No new export formats.

**D40 (2026-10-19): Image paths are relative when possible and absolute only when they must be; saves carry a thumbnail.** The project reader and writer now accept absolute image paths (only NUL bytes and paths over 4096 characters are rejected), so a project on one drive can keep an image on another. `project.save` and `project.saveAs` still rewrite paths relative to the file being written, rebase references that were relative to the old folder when the folder changes (Save As used to leave them pointing at the old one), and list the images that had to stay absolute in the result (`absolute_images`). The envelope gains an optional `thumbnail {width, height, png}` (base64 PNG, at most 512 px and 1 MiB decoded); the file version stays 1 because older readers ignore unknown fields. A save renders sequence 0 at t = 0.5, box-downscales it to 256 px and embeds it; any failure there only skips the thumbnail. Cost at 1080p with 50 dots: about 12 ms warm (45 ms cold, loading the images), so there is no reduced-size render.

**D41 (2026-10-19): File commands.** `file.new` makes a blank project with one empty sequence (kind, width, height optional) and `project.new` keeps its two-image form. `file.appendProject` adds another project's sequences (after a given sequence or at the end, undoable): the current project's output size, kind and face model win, a different project kind is refused, and image references are made absolute against the other file's folder so they resolve until the next save makes them relative again. `file.wizard` takes an ordered path list (the new `PathList` parameter kind: at most 1000 entries, each checked like a path; a form shows it as a list with Add, Up, Down and Remove) and builds A to B, B to C and so on, plus last to first with `loop`; every image is read before the project is replaced, so a bad file changes nothing. `frame.exportEdit` renders like `export.frame` and writes the dots as the frame draws them (shape curve and track included, via `Planner::dots_at`) with both sides of every pair equal, so the frame plus its dots can start a new sequence. `file.openVisual` lists projects (a folder and/or named paths, 500 per folder) as `{projects: [...], truncated}` with name, sequence count, kind, modified time and the embedded thumbnail, reading only the files' data; an unreadable project is an entry with an `error`. `ib run` gained `--save <file>` so a command that builds or edits a project leaves a file behind. Save As took Ctrl+Shift+S from `curve.shape`, which moved to Shift+Ctrl+H.

**D42 (2026-10-19): The shell asks before throwing work away and routes drops through commands.** `REPLACES_PROJECT` (`file.new`, `project.new`, `project.open`, `file.wizard`) is guarded: with unsaved changes the command is held and a Save / Don't Save / Cancel window opens. Recent files, Open Visually and dropped project files all dispatch `project.open`, so they are covered; a form stays open until the prompt is answered; Save with no file yet goes through Save As and carries on afterwards (cancelling Save As drops the action). Closing the window with unsaved changes uses the same prompt (`CancelClose`; skipped when taking a screenshot). `ViewState::recent` keeps 10 paths, newest first, fed by open, save and save as. Dropped files are classified by `dragdrop::route_drop`, a pure function: a project opens (and wins over the rest of the drop), one image goes to the panel it lands on (elsewhere: Image 1 if empty, else Image 2), several images open the wizard pre-filled in drop order, a dot file runs `dots.import`, anything else (or data without a file path, as in a browser) is a status-bar message. Effect slots are not drop targets yet, so `file.dragDrop` stays partial.


**D43 (2026-10-19): Source edits are one fixed, non-destructive pipeline per image.** Each image of a sequence has one `ImageEdit` applied in this order: geometry (quarter turns, then flips, then a crop rectangle in the turned and flipped picture with a content angle about the crop centre, optionally expanding the canvas), colour adjust, an ordered list of at most 16 filters, then the caption. Each command replaces only its own part. The file on disk is never touched; edits live in the project and the registry's snapshot undo covers them. All pixels reach the renderers through `Session::prepare`, so neither renderer changed. `Session::source` returns the raw cached `Arc` for an identity edit (so morph invariants and performance are unchanged) and otherwise caches the processed image by (path, hash of the edit JSON, font stamp), validated against the raw `Arc`, with a 32-entry LRU so undo and redo are free. Old files read as identity; identity edits are not written; the format version stays 1.

**D44 (2026-10-19): Dots follow their image through `ImageEdit::geometry`.** `geometry(src_w, src_h)` is the single definition of the edited size and the edited-to-source affine; pixels (`resample`, or exact permutations for turns and flips) and dot re-mapping both use it. Dots are in output-frame pixels (D12), so a geometry command maps each dot of that image through fit inverse (old), the old geometry, the inverse new geometry and fit (new) (every step affine, so exact), refuses a result with non-finite positions or two dots on one spot (D29), and `keep_dots` opts out. A missing source refuses geometry edits naming the image. Turning or flipping carries an existing crop with it; a mirror negates the angle and a quarter turn swaps the flip flags so the canonical turn-then-flip order holds. `sequence.add`, `link` and `copyFrame` copy the edit with the image; `image.swap` swaps images, edits and both sides of every pair.

**D45 (2026-10-19): Filters are bounded, deterministic pixel operations in `raster`.** Smooth (1-2-1 kernel, strength), box blur 1-100, Gaussian sigma 0.3-100 (true kernel below 2, three box blurs above), zoom blur, radial blur, sharpen (unsharp mask), emboss, mosaic 2-512, oil paint (radius 1-16, levels 8-256, sliding histogram per row), splash (scatter from a hash of x, y and the seed), cylinder, whirl, pinch. Parameters outside their range are errors in the document and clamped (NaN neutral) in `raster`, a neutral parameter returns the input exactly, and rendering is row-parallel but identical across thread counts. Timings are in `docs/perf.md`; adjust and Gaussian miss their first targets and are the first things to optimise.

**D46 (2026-10-19): Captions have three scopes and are drawn on the CPU.** A `Caption` (text up to 4096 bytes, font file or the bundled Roboto, size in frame pixels, bold, italic, colour, border, alignment, anchor x/y as frame fractions with y the middle of the block, shadow with angle, distance, colour and size where size 0 is none) lives on an image edit, on a sequence, or on the project. Layout uses `ab_glyph`; bold is three offset draws of 1/24 em, italic a 0.2 shear about each baseline; the border is a disc dilation, the shadow the blurred silhouette of text plus border. A caption is drawn once into a frame-sized layer. The image caption is drawn last in `apply_edit` so it morphs with its picture; the sequence caption is laid over each frame after the effects and before the master fade; the movie caption is laid over every frame handed to `render_movie`, `export.frame` and the shell preview. A visible caption sends the preview to the CPU (as effects do, D34). Font files are project paths (rebased on save, absolutised by append, cached by file stamp, at most 32 MiB). A caption wholly outside the frame draws nothing and border or shadow reach beyond the frame is limited to 256 px.

**D47 (2026-10-19): `image.saveToLibrary` saves what you see.** It writes the processed source (`Session::source`) and converts the dots through the inverse fit on the edited size, so `face.library use` restores the picture with the dots on the same features. `dir` stays required in the engine; the shell remembers the last folder in `ViewState` and pre-fills the form.

**D48 (2026-10-19): Key dots can be unpaired, joined by lines, and selected in the engine.** `DotPair` gains `side: Side { Both, Only1, Only2 }` (default `Both`, written only when not `Both`, so old files round-trip byte for byte and the version stays 1). The missing end of an unpaired dot is stored equal to the present end, so an older reader sees a harmless fixed anchor. `DotSet::first_positions`, `second_positions` and `interpolated` return paired dots only, so the planner and both renderers ignore unpaired dots untouched. `DotSet.lines` holds `Line { a, b }` pair indices (organizational only, never reach `morph`); `DotSet::remove` is the one way to delete a dot and renumbers or drops the lines, `validate_lines` (in `Sequence::validate` and the dot-file reader) rejects out-of-range, self and duplicate lines. `DotPair::has_end/end/set_end/swap_ends` keep every end-aware edit (`dots.move`, geometry remaps, `image.swap`) honest about unpaired dots. Selection, the dot clipboard and `DisplayPrefs` live on `Session` (not in the project, not undone); the selection is cleared when an edit, undo or redo changes the dot count and clamped otherwise. Index and coordinate lists are `ParamKind::IntegerList` and `NumberList`.

**D49 (2026-10-19): The movie has a frame rate and a size you can change; the preview can play the whole movie.** `Project::fps` (1 to 60, default 24, written only when not 24, so old files are unchanged and the version stays 1) is the one frame rate: playback, exports that take no `fps`, and `sequence.length` in seconds (`seconds`, `hold_start_seconds`, `hold_end_seconds`, rounded to frames; `apply_all` is all or nothing) use it; `movie.fps` sets it. `movie.size` (width and height, a preset, or `match_image`) moves every dot through `fit_new⁻¹ ∘ fit_old` of its image (stretch needs no source; contain and cover read the edited source size and refuse a missing file unless `keep_dots`), and scales sequence and movie captions by the height ratio; image captions live on the picture and are untouched; camera, effects, track and crops are fractions or source pixels and need nothing. `Session::render_movie_frame` and `movie_thumbnail` render any movie frame (layers stacked) and back `export.frame movie_frame` and the frame strip. The shell's preview has two scopes (`ViewState::preview_scope`): in Movie scope on a sequence project the shell selects the sequence the playhead is in, so every panel still works on `state.frame` as a frame of the selected sequence; on a layer project the preview is the CPU composite.

**D50 (2026-10-19): Shell-only view actions live in one table.** `ui-egui/src/actions.rs` lists zoom, link, layout, fullscreen, scope and toggle actions with their ids, labels and keys; the View menu and `handle_keys` both read it (more modifiers are tried first, so Alt+Ctrl+0 is not Ctrl+0), and a test keeps every key parseable and unique across these and the engine's commands. Zoom presets are 12.5% to 800% (keys, menu), the wheel reaches 1600%; egui's own keyboard zoom is off so Ctrl+= and Ctrl+- reach the panels. Layouts (F5 to F9, F11) are view state; Dual opens the preview in an immediate second viewport (an embedded window where the backend has one window only). Splitters write `top_fraction` and `left_fraction`. The preview view can follow the sources (`view.syncPreview`), carried so the same part of the frame stays centred.

**D51 (2026-10-19): Undo is limited by memory, not by a step count.** The history keeps at least 200 steps and drops the oldest once its estimated size passes 256 MiB (a flat cost per sequence plus the dots), with a hard stop at 100,000. After an undo or redo, a still-open Adjust or Caption window starts a new group so the rest of its session stays one step.

**D52 (2026-10-20): A bundled detector places the face model, in pure Rust.** `crates/detect` (L2, `inbetween-detect`) runs two ONNX models with `tract-onnx` (MIT or Apache-2.0, pure Rust, builds for wasm32, deterministic): the MediaPipe short-range face detector (128 px input, 896 anchors, box and eye keypoints) finds faces, then the 468-point mesh network runs on a square crop rotated so the eyes are level (scale 1.5, 192 px) and its points map back through the inverse affine. Models, conversion commands and SHA-256 hashes are in `crates/detect/models/README.md`; the weights are Apache-2.0 and embedded by the default `bundled-models` feature (about 2.8 MB), and the engine's default `face-detect` feature pulls the crate in (slim builds drop both and `face.locate` falls back to a box). Excluded: dlib's 68-point model (trained on a non-commercial data set, so it fails rule 8) and the attention/iris variant (custom operators no converter handles; pupils are the mean of the four eyelid points). Wide or tall images are also searched in overlapping square windows (run on scoped threads, with an inline fallback where threads cannot start) so small faces are not squeezed into a thin letterboxed strip. `mesh_map` is Inbetween's own table from standard-model landmark names to mesh indices; a landmark the table does not know is placed by a least-squares similarity fit from the known ones, so custom models still work. The mesh stops at the forehead, so the three hairline landmarks are approximate (smart drag fixes them). `face.locate` gains `source` (`detect`, `box`, `landmarks`; the default is `detect` unless a box or a landmarks file is given), `face` (best first), `all_faces` (left to right; both images must show the same number of faces) and `layout: mesh478` (a 468 or 478 point mesh from another tool, with iris centres placing the pupils when 478). Detection runs on each image's processed source and maps through the sequence fit, so the two images get their own points; a missing face is a `BadParams` error that changes nothing. `face.detect` reports faces read-only, `face.locateAll` is `face.locate` with `all_faces`, and `face.extract` detects first when no face is placed at `first`. Detections are cached by source image (weak references, 8 entries) so a repeat after undo runs no inference.

**D52 addendum (2026-10-20): the conversion is checked, and the slim build is tested.** `reference::converted_models_match_the_tflite_reference` runs both converted files in tract on fixed inputs and compares them with outputs the original TFLite models produced (committed in `crates/detect/tests/data/reference/`): max difference 0.0003 (detector regressors), 0.0007 (scores), 0.0001 (mesh points), 0.00002 (presence), against output values up to about 230. The slim build (`--no-default-features` on `inbetween-detect` and `inbetween-engine`) is linted and tested by `cargo xtask ci`: `Detector::new` returns an error, `face.locate` defaults to a box, and detection requests fail with advice to give a box or a landmarks file.

**D52 addendum 2 (2026-10-20): the detector is run on wasm32, not only compiled for it.** The `wasm_check` example, built for `wasm32-wasip1` and run under Node's WASI, loads both models in tract, finds the face in a portrait and prints the same numbers as the native build (`crates/detect/models/README.md`). `cargo xtask wasm` stays the compile gate; the run is by hand because it needs Node and the extra target. It also covers the no-threads path (`spawn_scoped` fails and the windows run inline).

**D53 (2026-10-20): The MCP server is a hand-written stdio JSON-RPC loop with one tool per command.** `crates/mcp` (L6, `inbetween-mcp`, depends on the engine and `serde_json` only) serves newline-delimited JSON-RPC 2.0 on stdin and stdout; `ib mcp [--project p.inbetween]` runs it. A tools-only server needs five methods (`initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`), so there is no async runtime and no MCP SDK; the loop is small enough to fuzz. Protocol versions 2025-06-18, 2025-03-26 and 2024-11-05 are accepted (the client's is echoed, otherwise the newest answers). Every registry command is one tool: the name is the id with dots turned into underscores (`export.frame` is `export_frame`; the Claude API allows only `[a-zA-Z0-9_-]`), and `inputSchema` is generated from the command's `ParamSpec`s (ranges, choices, list bounds, defaults and path use in the descriptions, `additionalProperties: false` because `Params::parse` rejects unknown keys), so the list cannot drift from the registry. One `Session` lives for the whole connection, so edits persist and `edit_undo` works. Protocol faults are JSON-RPC errors (-32700 parse, -32600 invalid request, including batches, -32601 unknown method, -32602 unknown tool or bad `arguments`); a failing command is a normal result with `isError: true` and `structuredContent {code, message}` using `CommandError::code()`. Every call goes through `Registry::run_caught`, lines longer than 64 MiB are skipped with an error, and stdout carries nothing but protocol messages (problems go to stderr). A result with a `png_base64` field is returned as an MCP `image` block instead of text. `frame.preview` (new engine command, also usable from `ib run`) renders any frame scaled to `max_size` (16 to 4096, default 512, never enlarged) and returns that field, so an agent can look at its work. Open: resources and prompts, progress and cancellation for long exports, an HTTP transport.

**D54 (2026-10-20): The sequence list is where order, copying and project type are edited.** Dragging a row by its title onto another row runs `sequence.reorder` with `to` (the dragged sequence takes the target's position); dragging a thumbnail onto another row's thumbnail runs `sequence.copyFrame` (`from_image`, `to_image`; the source keeps its image and the other end of the target's dots starts unmoved). `seqlist::drop_action` is the pure rule (a row onto itself, an image onto its own slot, or an image onto a bare row does nothing). Thumbnails are drag-only, the row is click-only and the title is a separate drag handle created last, because egui sends a drag to the top-most widget that senses drags; rows are drop targets by pointer position since the handle and thumbnails cover them. A combo box beside the heading switches `project.type` (In order, Layers); in a layer project each row reads `name (layer N, top|below)` and the footer says the movie is stacked. In a layer project the shared length is the movie's: it lasts as long as the longest visible layer and a shorter layer holds its last frame (D36); `sequence.length` with `apply_all` gives every layer the same length when that is wanted.

**D55 (2026-10-20): Sequence effects move with the camera (the camera zone).** `Renderer::render_at` now runs: morph (transition inside), trail of earlier *morph* frames in the sequence's own space, effects, camera, sequence filters, caption, master fade. The camera moves the finished composite, so a back colour or background fills only the camera's frame and the pixels outside it are transparent, letting movie effects or lower layers show there. With no camera move the output is byte-identical to before. The one behaviour change: a trail no longer smears camera motion, because it is taken before the camera.

**D56 (2026-10-20): Movie-level effects use the same commands with `scope`.** `effect.backColor`, `background`, `mask`, `foreground`, `light`, `radial` and `trail` take `scope` (`sequence` default, `movie`); `sequence` is ignored at movie scope and `effect.transition` at movie scope is a `BadParams` error (it needs two images). `Project::effects` is written only when it differs from the default. The engine's `MovieFinish` (effects, adjustment, filters, caption, with images loaded through the session cache) is applied to every frame by `render_movie`; radial and light use movie progress as `t`. The movie trail widens the range backwards (forwards when reversed) by its past-frame count and keeps a ring of earlier frames, so one frame comes out the same as inside an export. The shell's sequence-scope preview applies the pass through `Prepared::finish` but has no earlier movie frames, so it shows no movie trail.

**D57 (2026-10-20): Output colour and filters reuse the image ones.** `movie.adjust` edits `Project::adjust`; `movie.filter.<name>` (and `remove`, `move`, `clear`) edit a filter list at `scope=movie` (default) or `scope=sequence` (`Sequence::filters`, run after the camera). The filter constructors were lifted out of `image.filter.*` (`build_<name>`) and one seam, `edit_filters`, changes the list an `image`, `sequence` or `movie` scope points at; the movie schemas are derived from the image ones. At most 16 filters per list.

**D58 (2026-10-20): One sound track per movie, decoded in pure Rust, muxed by ffmpeg, played with cpal.** `Project::sound` (`path`, `looped`, `cut_at_end`, `fade_in`, `fade_out`, fades 0 to 60 s) is written only when set, and its path is rebased with the others. `crates/audio` (L0) decodes WAV with `hound` (Apache-2.0) and MP3 with `puremp3` (MIT or Apache-2.0, pure Rust, checked with `cargo deny`), capped at 30 minutes or 1 GiB of samples; a panic inside the MP3 decoder is caught and becomes an error. `export.video` adds `-stream_loop -1`, `-map`, `-c:a aac` (`libopus` for WebM), `afade` filters and `-t` (see `ffmpeg_args`, unit-tested); `audio=false` leaves it out. GIF, APNG and WebP report `audio: skipped (format has no sound)`. The shell plays through a `cpal` output stream resampled linearly to the device rate, follows the transport and re-seeks when it drifts 0.2 s; a missing device is a status message. Playback needs `libasound2-dev` on Linux.

**D59 (2026-10-20): Exports have no GPU size cap, can pick a sequence and can be cancelled; video encoding stays with ffmpeg.** Every export renders on the CPU (`render-gpu` serves only the live preview, which falls back to the CPU on `TooLarge`), so an output wider than any texture limit exports normally (regression test: 20000 x 16). `export.movie`, `export.animation` and `export.video` take `sequence` (one sequence of the movie; `first` and `last` then count inside it; refused for layer projects and hidden sequences). `export.frame` takes `quality` (JPEG, 1 to 100) and `dpi`; sequence and movie PNG exports take `dpi`, written as a `pHYs` chunk or the JFIF density by `codecs::set_png_dpi` and `set_jpeg_dpi`. `Session::cancel_handle()` returns an `AtomicBool`; setting it makes the running export stop at the next frame with `CommandError::Cancelled` (code `cancelled`), and the flag clears when the next export starts. MP4, WebM (VP9 with alpha) and ProRes 4444 are written by an installed ffmpeg; a bundled encoder is not planned, so `export.video` is complete as specified.

**D60 (2026-10-20): Effect cameras, aspect locks and the camera tool.** `Effects::cameras` (`EffectCameras`: one `Camera` each for background, mask, foreground, transition and light, written only when not default) is moved by `render-cpu::effects`: the effect's picture is stretched to the frame, put through `camera::apply` at the sequence's morph time (the movie's progress for movie effects), and the area it leaves is transparent for background and foreground, white for a mask and mid-grey for light and transition so those read as neutral there. `effect.camera` (params of `camera.keyframes` plus `effect` and `scope`) edits them. `camera.keyframes` gained `op` copy and paste (a one-camera clipboard on the session, outside undo) and save and load (`.inbetweencamera`, `inbetween-camera` version 1, in `crates/format`), and `aspect` now means free, movie (also `locked`), image1 or image2: with a lock, setting one scale derives the other so the camera frame keeps that shape (`|sx|/|sy| = (w/h of the image) * (H/W of the movie)`). The shell's Camera window and preview handles (`camera_tool.rs`, pure geometry) draw the moved picture's outline: drag inside to move, squares to scale (the far side crossed flips), the circle to rotate; each drag step is an `op=set` at the playhead's time inside one undo group. The Curves window also edits the master and camera curves.
